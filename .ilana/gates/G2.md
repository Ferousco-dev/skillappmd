## §A — Six design objectives

**Correctness.** The corpus supplies **row-level oracles** — `dedup_primary` and
`frontmatter_valid` — so dedup and parsing are validated against published ground truth rather
than against fixtures we invented. Measured `dedup_primary` = 50.2% vs the paper's 50.5%.
Correctness invariants are enforced at write time (`NFR-004` attribution, `NFR-006` rights), so
violations are unrepresentable rather than merely detectable.

**Completeness.** All 150 requirements map to design. Nine subsystems are deliberately deferred,
each with the single mechanism that keeps it buildable (`ARCHITECTURE.md` §6). Deferral is
recorded, not discovered.

**Efficiency.** Computed, not assumed: full known corpus ingests for ~$17 once, ~$2/month.
`DEC-026` (JSON provenance) cuts storage 44% and doubles D1 headroom. The 9→4 queue-stage collapse
is designed and costed ($200/full ingest at 100M) but **not built**, because at Phase 1 scale it
saves $0.00 and costs observability.

**Flexibility.** Ports with ≥2 adapters each, enforced by dependency lint (`NFR-028`), not review
discipline. The falsifiable test: the Postgres adapter can be written and the full suite pass
without editing `skill-core/` or `ingestion/`. That is a **G4 criterion**, not a claim.

**Consistency.** One `SourceConnector` contract serves a local Parquet corpus and a keyword-only
rate-limited API — deliberately the two most different sources available, so the abstraction is
tested rather than assumed. One response envelope, one pagination rule, one timestamp format.

**Maintainability.** `skill-core` is pure: rights, licence and identity — the parts most likely to
be wrong and most expensive to get wrong — are testable exhaustively with no infrastructure. Every
document states purpose, inputs, outputs, failure modes, scaling and testing (BRIEF §65).

## §B — Alternatives considered and rejected

| Rejected | Reason |
| --- | --- |
| **D1 sharded across 50k databases** | Buys capacity by permanently adopting shard routing, cross-shard queries, per-shard migrations and backups — to defer a one-time migration. `DEC-021`: that is *building* future scale (`DEC-027`) |
| **PostgreSQL from day one** | Costs an account, a Workers connection story, and ops burden for capacity Phase 1 will not use for years (`DEC-027`) |
| **MongoDB** | Document shape genuinely fits, but Atlas free tier (512 MB) is too small even at 1M, there is no Cloudflare integration, no local-dev parity, and a later move is a rewrite rather than a port (`DATABASE.md` §5.3) |
| **Durable Objects / KV / R2 / Vectorize as canonical** | Consistency primitive, eventually-consistent KV store, object store, and disposable similarity index respectively. None is a record store (`DATABASE.md` §1) |
| **Microservices from the start** | Distribution costs today for independence not needed until 100M+. Modular monolith draws the boundaries; the network is crossed later, if ever (BRIEF §58) |
| **Single runtime** | Parquet needs a filesystem, real memory and DuckDB; Workers has none. Pretending otherwise yields an architecture that cannot be built (`DATABASE.md` §7) |
