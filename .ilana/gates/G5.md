## §A — Why this gate fails

`DEF-008`. **`REQ-004` (`SkillsMPConnector`, priority M) and `REQ-028` (skip re-fetch when the
source reports content unchanged, priority M) were never implemented.** `REQ-005`, `REQ-014` and
`REQ-025` are absent too, at priority S.

**How it stayed hidden is the part worth recording.** `TC-260` was titled *"REQ-004/DOM-012 every
connector declares an enforceable access policy"* and exercised only `GitSkillsCorpusConnector`.
The traceability matrix is generated from test titles, so **`REQ-004` read as covered.**

A test naming a requirement it does not exercise is worse than an uncovered requirement: an
uncovered requirement is visible; a falsely-covered one is not.

Root cause, same as G4's: `ROADMAP.md` increment 3 was scoped to `REQ-001`–`003`. **`REQ-004` was
never assigned to any increment.** The design was right — `SOURCE_CONNECTORS.md` §4 specifies the
connector in detail — and the plan lost it. Twice now, the plan has been the weak link rather than
the architecture.

`TC-260` is retitled to what it proves. An audit of every test title naming a requirement found no
other instance, and `packages/tools/src/traceability.js` now runs in CI so the next one surfaces
immediately.
