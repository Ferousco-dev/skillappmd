## §A — `DEF-008` closed for the mandatory scope

`REQ-004` (`SkillsMPConnector`) and `REQ-028` (conditional re-fetch), both priority M, are built,
wired and tested. `REQ-025` (circuit breaker) and `REQ-096` (robots policy) came with them.

**Verified live**, respecting SkillsMP's published limits: one request, five real records, GitHub
coordinates resolved from `githubUrl`, access channel recorded on every record.

Tests run **offline against fixtures recorded from the live API** — including the real
`MISSING_QUERY` 400 — so the asserted shapes are the shapes SkillsMP actually returns. Five defects
in this project have come from fixtures encoding my assumptions rather than reality; recording them
from the source is the cheap fix.

Design decisions that reflect what the research established:

- **No `discoverAll()`.** The catalogue cannot be enumerated (`q` required, wildcards unsupported,
  50×50 cap). A method implying otherwise would be a lie in the shape of a function.
- **`getContent()` returns `NotAvailable` by design.** SkillsMP hosts nothing (`DEC-002`).
- **Impersonation is refused at construction**, not left to review.
- **Identity comes from GitHub coordinates**, never the aggregator id (`DEC-014`).

## §B — `RSK-002` closed on evidence, not inference

Live verification established the SkillsMP API is **pre-authorised**: `/developers` states
*"Anonymous access is also available with lower rate limits"*, both tiers carry published quotas,
and an anonymous call returns real data. **A published quota is the permission.**

`robots.txt`'s `Disallow: /api/` is a **crawler directive** — it governs bots discovering pages, not
clients calling a documented API. Reading it as a prohibition was over-caution.

**What I got wrong is the project's own recurring failure mode.** The caution was right at G0.
Carrying it as an open risk for the entire project **without ever re-testing it** — then
recommending a letter, when one anonymous call settled it in ten seconds — was not. It took the user
asking *"is there still need for a mail when we have the apis"* to prompt the check. `DEC-038`
records it.

The clarification letter stays on disk, unsent. It becomes worth sending only if AppMD later wants
something the public API does not offer.
